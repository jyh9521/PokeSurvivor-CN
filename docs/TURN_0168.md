# 0.16.8：直连失败后的 Cloudflare TURN 备用连接

基线：`4366d82e6a41f379f01885883281fc82573de788`（0.16.7）。通信协议14；账号存档schema仍为3。没有改动近战、成长数值、技能进化或存档经济。

## 玩家体验与根因

上一版只有STUN，直连失败后缺少独立中继，又保留周期性重试，导致房间长时间显示“连接中”。本版保留房主浏览器模拟，但补齐独立TURN路径和有限失败状态：

1. 优先玩家直连；成功的连接不申请TURN凭证。
2. 直连失败或6秒未建立时，NAS校验当前账号、在线会话及房间，向Cloudflare申请短期TURN凭证。
3. 战斗数据通过 **Cloudflare Realtime TURN** 转发，而不是NAS。支持UDP、TCP和TLS候选；没有把普通Cloudflare反代/Tunnel/Worker当作UDP中继。
4. TURN协商窗口12秒，总连接尝试最多26秒。两条路径都失败、未配置TURN、用量查询失败或额度保护触发时，结束本次尝试并说明原因，不无限自动重试。
5. 大厅提供显眼的逐人重试、重试全部、原有转移大厅房主及退出。等待状态逐秒更新，但不每秒销毁按钮，保留键盘/手柄焦点。战斗中网络诊断提供重试和退出入口。
6. 显式重试会清除失败的客户端凭证缓存；新的主机offer能恢复已经终止等待的队友，并重置其截止时间。可靠事件序号保持，断线积压只通过RTC补发并去重。
7. 发布包显示真实“Cloudflare TURN”或直连/混合路径，依据选中ICE候选对判断；失败/等待状态不拿NAS的1ms测速冒充战斗RTT。
8. 原主机与主动主机迁移继续工作，包括TURN连接中的检查点交接和原run凭证转交，不重开对局或重复发奖励。

最小差分探针：同样让直连没有候选，时钟推进到6001ms，基线只有1个RTC尝试、TURN凭证请求0、无手动重试；本版有2个RTC尝试、TURN请求1，备用尝试使用`iceTransportPolicy=relay`，且有手动重试入口。NAS战斗数据包始终为0。

## 不需要购买VPS或部署Worker

使用你自己的免费Cloudflare账号创建 **Realtime TURN key** 即可使用托管TURN。NAS仅负责后端鉴权和凭证签发；不需要独立服务器、额外域名、NAS的UDP入站端口或Workers付费计划。项目旧的`cloudflare/turn-worker.js`只对应历史Firebase体系，本流程不使用它。

官方入口与契约：
- [创建TURN key及短期凭证](https://developers.cloudflare.com/realtime/turn/generate-credentials/)：长期key留在后端，网页仅获得有期限的连接凭证；本版TTL为3小时，连接存续时提前刷新配置。
- [Realtime计费](https://developers.cloudflare.com/realtime/sfu/pricing/)：SFU/TURN共享每月1,000GB免费额度，超出后按官方价格收费，不是无限免费。
- [TURN Analytics](https://developers.cloudflare.com/realtime/turn/analytics/)：通过账号级GraphQL查询TURN出口用量，不只看当前游戏的key。

### 额度保护的准确含义

- 默认`CF_TURN_CAP_GB=100`，即观测到的账号TURN用量＋其他Realtime预留达到100GB时，停止签发新的TURN凭证。可配置大于0且不超过900GB。
- `CF_TURN_OTHER_USAGE_GB`用于预留其他SFU等共享免费额度用途；只有本游戏TURN时填写0。
- 必须提供只读Analytics Token；查询错误、权限错误、数据缺失/非法时停止签发，而不是忽略错误继续消耗。
- 查询缓存30秒；签发按账号限流、按账号/房间合并缓存，已有直连不受额度保护影响。
- **这不是Cloudflare官方账单硬停，也不是零超额保证。** Analytics有延迟/采样，已签发的3小时凭证不会因停止新授权而立即失效；其他服务也共享免费额度。仍应查看Cloudflare账单/用量，并在不接受超额计费时停用TURN key。向导在配置前明确说明并要求确认，不自动开通付费订阅。

## 一次性设置（在NAS终端操作）

先拉取包含0.16.8的main，然后运行向导：

```sh
WORKDIR="$(mktemp -d /mnt/user/appdata/pokesurvivor-update-XXXXXX)"
git clone --depth 1 --branch main https://github.com/jyh9521/PokeSurvivor-CN.git "$WORKDIR"
cd "$WORKDIR"
bash deploy/setup-cloudflare-turn.sh
```

向导共5步，会打印官方网址；NAS没有浏览器时在电脑打开网址即可：

1. 阅读并确认Realtime当前免费额度与计费条件。
2. 在Cloudflare账号复制 **Account ID**。
3. 在[Realtime/TURN](https://dash.cloudflare.com/?to=/:account/calls)创建本游戏专用key，复制 **TURN Token ID**、对应 **API token**。若界面要求付费订阅而你只接受免费方案，停止并核对当前开通条件。
4. 在[API Tokens](https://dash.cloudflare.com/profile/api-tokens)创建 **Account / Account Analytics / Read** Token，范围仅包括该账号；填写其他Realtime预留量，无其他用途填0。
5. 写入NAS私有配置。Token输入隐藏，不打印值，不提交Git，也不发送到网页。

默认生成：

- `/mnt/user/appdata/pokesurvivor-cn/turn.env`：Docker使用的纯`KEY=value`文件，权限600。
- `/mnt/user/appdata/pokesurvivor-cn/.turn-wizard.env`：向导重跑/续填状态，权限600。

自定义配置目录可使用 `CONFIG_DIR=/你的配置父目录 bash deploy/setup-cloudflare-turn.sh`。向导只生成配置，不会更新正在运行的容器。

### 当前 NAS 更新入口（0.19.0）

见 [Unraid 部署与升级](UNRAID.md)。Compose 与独立容器必须使用各自入口，并显式给出 project 或容器名以及原数据目录。不要再传单个 Origin 参数，也不再通过 TURN_ENV_FILE 隐式覆盖运行配置。

新安装 Compose 时，把向导生成的 CF_* 值合并到既有 `.env`（权限600），保留 HOST_PORT、DATA_PATH、PUBLIC_ORIGIN 等值；独立 Docker 初次创建时可使用 `--env-file /绝对路径/turn.env`。不要用仅有 TURN 参数的文件替代整个部署环境。

既有容器更新器保留实际环境，并在停止旧容器前验证已有 TURN 权限和短期凭证。新增或轮换 TURN 密钥是单独的配置变更，应先按自己的容器管理方式在维护窗口应用并验证，确保 Compose 配置与实际容器一致，再执行代码升级。仅生成 turn.env 不代表线上已启用 TURN。更新后保持维护，所有玩家刷新至协议18，验收后手动开放。
