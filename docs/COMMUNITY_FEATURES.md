# 社区版 0.3.0

## 1. 玩家直连与回退

游戏数据优先使用 WebRTC DataChannel，仍是房主与各队友连接的星形拓扑。
账号验证、双份存档的 NAS 副本、好友关系、排行榜和房间授权始终由原 NAS 负责。
连接信令通过认证 WebSocket，仅能发给同一房间的合法对端；开始游戏的队伍由 NAS 确定。

通用模块 `js/net/direct-link.js` 不依赖语言和数据库：

- 默认使用 Cloudflare / Google 公共 STUN 发现可达地址；没有 TURN、付费凭据或 Firebase 请求。
- 协商期间立即使用原 NAS 中继，不让玩家等连接。9 秒协商超时后保留中继；房主每 15 秒重试直连。
- 直连关闭、失败或积压时，继续通过 NAS 发送；无需额外开放 NAS UDP 端口。
- 状态序号只接受最新帧。事件独立排序、确认、去重，800 ms 未确认便通过 NAS 重传。
- 每个对端最多保留 256 个未确认事件 / 待排序事件；超限退出房间，不静默丢弃消费和选择。
- 开始游戏及诊断 NAS 往返探测继续使用 NAS 控制通道。诊断增加直连 / 中继数量及未确认事件数；房间 RTT 标签仍明确是 **经 NAS**，不冒充直连 RTT。
- 掉线期间不继续绕过 NAS 的房间授权。退出房间销毁 RTC 连接、队列和序号。

实现依据：[RTCDataChannel](https://developer.mozilla.org/en-US/docs/Web/API/RTCDataChannel)、[RTCPeerConnection](https://developer.mozilla.org/en-US/docs/Web/API/RTCPeerConnection)。
STUN 不是数据中继；复杂 NAT 下可能无法直连，此时 NAS 接管，不要求购买 TURN。

## 2–3. 重复补偿与五星不重复

维持原概率：1★ 45%、2★ 30%、3★ 17%、4★ 6.5%、5★ 1.5%。十连和 70 抽保底继续生效。

|重复普通结果|返还抽奖券碎片|
|---|---:|
|1★|10|
|2★|20|
|3★|40|
|4★|100|

100 碎片自动转成 1 张单抽券，余数留在 `tickets.fragments`，浏览器和 NAS 一同保存。
新获得的异色属于新的收集结果，不作为普通重复返还；已有异色继续优先选择未获得的同稀有度异色。
金币余额不因重复抽取变化，不回溯兑换以前已领取的金币。

所有五星（包括传说、幻之宝可梦和准神）只从本池尚未拥有的物种选择，不以异色规避此规则。
本池五星物种已集齐时，五星结果直接显示并发放 **2 张单抽券**，不显示或发放重复宝可梦，保底计数重置。
不跨世代重选，不悄悄改成四星，也不取消原概率。

## 4. 断线重连

认证 WebSocket 断开后保留房间成员 30 秒。原页面每 3 秒重试连接，复用原账号 Cookie；回来后继续同一场对局。
队友状态连续 2.5 秒未到达即暂停团队，不必等 TCP 关闭；掉线期间团队暂停，升级和道具选择队列不被当成退出清除；事件确认队列补送，周期敌人元数据修复遗漏的生成信息。
主动退出 / 登出 / 删除账号立即退出；超过宽限期，房主离线关闭房间，队友离线移除对应成员。
此功能针对短暂网络中断；关闭或刷新网页导致浏览器内的运行时丢失，不属于恢复整局的功能。没有房主迁移，也不将战斗模拟搬到 NAS。新页面使用新的运行时标识，会退出旧房间，避免把空白运行时误接回旧局；原页面断线重连使用原标识。联机接口要求 protocol 2，旧版本玩家刷新后才能加入，避免混用通信格式。

## 5. 中文昵称

`users.nick` 是新增可空列（schema 3），登录名称、UID、密码哈希和已有存档不变。
昵称允许 2–16 个汉字 / 字母 / 数字 / `_·-`，采用 NFKC 规范化，拒绝 HTML、控制字符和方向覆盖符号。
昵称可重名；好友申请始终用稳定 UID 区分玩家。玩家文本以 textContent 或 HTML 转义显示。
菜单、好友、房间、资料和历史排行榜显示当前昵称；登录仍填写原账号。
在“设置 → 账号”保存昵称。昵称不会修改金币、存档修订或福利收据。

## 6. 合作体验

- 集合 / 求救 / 危险标记：桌面 R / F / T 或手机按钮，3 秒冷却、8 秒显示。
- 房主校验标记种类、坐标范围和冷却，再转给其他队友；没有任意文本聊天或公开管理按钮。
- 队友面板显示姓名、生命值、倒地救援进度，地图边缘仍有原方向提示。
- 原靠近 56 像素自动救援保持不变；1 人救援约 3 秒，2 人约 2 秒，3 人约 1.5 秒。救援后仍恢复原 50% 生命，无额外金币或刷奖励入口。

## 7–8. 排行榜社交

每个玩家名字都可打开其资料，按 UID 申请好友 / 接受请求；已有好友与已发送请求显示对应状态，不重复申请。
排行榜每个队员分别显示在线 / 离线，前台每 10 秒刷新，资料弹窗打开时不刷新覆盖操作。
在线定义为 NAS 当前认证 WebSocket 已连接，不表示一定正在战斗；宽限期离线仍显示离线。
排行榜接口、好友操作均需登录；不公开玩家登录账号、IP、会话或存档。

## 构建、测试和更新

```sh
npm run test:nas
npm run test:nas:browser
node tests/community-browser.cjs
python tools/make_zh_font.py
npm run build
npm test
npm run test:nas:production
```

旧 NAS 中继回归显式关闭 RTC，检验回退路径。新增三浏览器测试使用真实 RTC（本机 ICE，无外部 STUN），测试真实通道失败、中继补送去重、房主 / 队友短断线、救援、昵称、好友、在线状态和抽卡 UI。
本地测试不等于中国与日本之间的实际链路测量，也不等于已更新用户 Unraid。

Unraid 原克隆安装更新命令，保留 `/data`、账号、存档、百万金币收据和历史成绩：

```sh
cd /mnt/user/appdata/pokesurvivor-cn/app && \
git pull --ff-only origin main && \
sh deploy/update-unraid.sh 'https://pokemon.blfy.cc:9521'
```

更新脚本先构建并备份 SQLite，使用原数据挂载，验证健康和公网 Origin；失败自动恢复旧容器。
人工回滚必须同时保留当前数据库快照。schema 3 为新增列，旧版本忽略昵称，但不会删除这列或更改登录密码。
播放器历史恢复 / 导入仍然禁用，管理工具不在玩家界面出现。
