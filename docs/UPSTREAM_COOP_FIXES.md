# 上游联机与裂隙修复移植

来源：JPTER78/pokesurvivor 的 b297089（2026-10-14），基线 5374405。

## 范围

只移植 js/net/coop.js、js/systems/rift.js 及 js/game.js 中选择界面相关变更。
没有合并 game.js 的排行榜提交/存档频率改动，也没有合并 Firestore 规则、官方榜单重置、好友时钟逻辑或封禁功能。

- 每个状态帧重复传递选择状态与升级轮次，补偿一次性开始、结束、选卡通知丢失。
- 道具选择与升级选卡串行处理；未完成的道具选择在选卡后重新打开。
- 本地补充：新一局清空待选道具；连续道具进入同一队列，避免覆盖未完成选择。
- 非房主退出裂隙不再清空远端敌人；房主仍恢复自己的敌人暂存区。

NAS 登录、双份存档、一次性百万金币活动及玩家历史恢复禁用规则保持不变。

## 验证

`node --test tests/coop-rift.test.cjs` 对原代码能复现四种失败：升级开始通知丢失、选卡完成/恢复通知丢失、道具暂停通知丢失、裂隙返回晚于房主恢复敌人。修复后的同一组行为测试通过，同时检查房主恢复逻辑未被移除。

`npm run test:nas:browser` 使用实际 HTTP、SQLite、WebSocket 与两个游戏实例：在 WebSocket 发送处仅丢弃一次性选择通知，周期帧仍经过 NAS 转发；检查两种道具/升级先后顺序及双方恢复。裂隙测试刻意延后客端退出，确认客端在退出前后都保留已恢复敌人的同一 ID。

这些是受控的真实浏览器回归，不代表已经在公网 NAS 上验收。玩家更新后应结束当前游戏并刷新到同一版本；更新脚本保留原账号、存档与奖励领取记录。
