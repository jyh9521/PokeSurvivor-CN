# 0.16.4 开发前审计（基线 0ce1d685）

## 实际路径与根因候选

- `Enemies.defFor` 由档位HP × 物种HP修正（0.7～1.6）×坦克1.5构建模板；`Spawner.spawnOne` 再应用 `enemyScale.hp × normalHp × tierBlend × partyHp`；`Enemy` 四舍五入，精英再×1.75。normalHp 已有上一轮额外时钟曲线，不能仅看任务书1.65。Boss独立模板×1.35，`bossScale=(1+t/600)*bossHp`，多人再×partyHp×1.4；裂隙自有模板。无玩家等级反馈。实际表见本地 `artifacts/balance/enemy-baseline.json`（含物种、精英、1/4/8人，0/180/600/1200/1800秒）。
- 64是普通生成目标预算，并非所有召唤和burst的硬上限。不能靠加怪解决压力。
- 输出：基础物攻系数 → 对应物攻/特攻六维修正 → 对应被动 → 等级 `1+.045*(L-1)` → STAB1.2 → 特性/特殊形态 → 敌人对应防御；属性天气及暴击在Combat结算。近战保护保持40%/22%/0.6秒，危险区独立强制判定。
- 经验：Spawner普通XP×5.6；精英×1.6、异色×5、金怪×2；Pickups拆14个Boss球时ceil会最多额外13XP，普通球只给一次。Game拾取按人数分配后gainXp一次乘xpMul；永久智慧最高×1.9，幸运蛋/局内学习又叠乘。xpFor仍为既有×4曲线，近期0ce1d685只改敌人HP，85dac14b改输出/精通，没有再次加速XP门槛。必须实测后调供给而不是再把门槛翻倍。
- LevelUp.active遍历`pl.moves`，按**招式ID而非实例**生成键；pick优先find首张进化，否则只从已有栏抽一张，未按当前组过滤。同名多实例时键不唯一；候选选择偏向某组不等于已证实闭包把组1写入组2：闭包实际捕获m。精通不限级且+6%基础伤害，缺卡原因包括未进化/满级判断和四栏只抽一张。新增实例ID、所有组显式目标选择和等待点，不虚构已复现所有玩家反馈。
- Battle被动最多3、四槽；成长同时有加法和乘法。守住间隔12-2L，直接放宽6会形成0间隔；反击时窗和伤害也读原始等级，必须用等效旧等级处理，不能只改上限。
- battle.used只在init设false，activate设true；没有裂隙重充。Rift.won有arena.id和fight phase防重放；finish才是成功返回点。奖励应从该点触发，活跃形态结束再重充。
- 房主权威敌人/击杀/XP；访客本地持有自身招式/被动/特殊状态；bh/bb与mh/mb递增去重。短断重连保留同一Player内存，无跨刷新恢复对局。Battle.net传被动等级但不传精通实例；新增运行态摘要字段、递增协议隔离旧版本，不迁移账号存档。
- 新wave/mark/decoy字段在updateFields只遍历敌人，遗漏场景物品；chain只找hurt敌人，物品成为target时直接找不到链首。待回归证明后补同几何物品命中。
- dash用0.8碰撞半径每8px找落点，再用完整半径挤出，可能落入夹缝；方向只跟敌人，自动瞬移覆盖玩家朝裂隙的移动。应全半径小步、玩家输入优先并保留伤害轨迹；世界碰撞同心点dx=dy=0时没有推离方向，另需脱困回归。
